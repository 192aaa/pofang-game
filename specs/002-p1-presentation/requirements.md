# 需求规格 002：P1 演出冲奖

继承 001 全部 AC（尤其 R6 降级：任何新演出不得引入白屏/中断路径）。
范围：破防慢镜头、透视模式、3 Boss。TTS 语音处刑另立规格评估，不在本规格。

## R1 破防慢镜头（胜利处刑演出）

**作为**玩家，**我想**在致命一击后看到一段慢镜头处刑演出，**以便**爽感落地、愿意录屏分享。

- AC1.1 致命一击（hp→0）后插入 ≤2s 的处刑演出：最后一击原文 + 巨大伤害数字 + 「破防！」印章式定格，深色遮罩 + 闪光/震屏。
- AC1.2 演出自动结束进入结算卡；点击/按键可立即跳过（评委动线不被阻塞）。
- AC1.3 失败局不做慢镜头，仅结算卡（保持节奏）。
- AC1.4 演出纯前端动画，零 AI 调用、零新增网络请求；mock 与 api 引擎表现一致。
- AC1.5 演出期间不改变任何对局数据（回合/血量/金句与结算卡一致）。

## R2 透视模式（双 LLM 幕后判定可视化）

**作为**评委/好奇玩家，**我想**打开透视看到每回合幕后判定数据，**以便**相信伤害不是随机数。

- AC2.1 头部提供「透视」开关，默认关；开关状态本局内保持。
- AC2.2 开启后每条室友回复下挂幕后卡：裁判原始 JSON（damage/hitType/reason）、演员/裁判耗时 ms、是否降级（演员/裁判分别标记）、玩家策略标签。
- AC2.3 关闭时零布局变化；旧服务端无 meta 字段时幕后卡显示「无幕后数据」而非报错。
- AC2.4 只暴露裁判输出与运行指标，**不暴露 system prompt / PAT / 内部路由**。
- AC2.5 mock 引擎提供同构模拟 meta（耗时为模拟值并标注「演示」）。

## R3 三 Boss 阵容

**作为**玩家，**我想**挑战不同嘴硬人设，**以便**复玩有新鲜感、路演有内容厚度。

- AC3.1 三个 Boss：阿伟·嘴硬室友（洗碗，现有）、卷王·室友（「我昨晚根本没复习」）、主席·学长（「白干活是锻炼机会」）。
- AC3.2 头部 Boss 切换 chips；切换即开新局（血量/回合/消息重置），当前 Boss 高亮。
- AC3.3 每个 Boss 独立：开场暴论、三阶段回复池、注入反嘲讽、认输/胜利文案、演员人设 Prompt；裁判锚点区间全 Boss 统一（难度不漂移）。
- AC3.4 URL `?boss=<id>` 直开指定 Boss（分享链接前置能力）；非法 id 回退阿伟。
- AC3.5 战绩卡 Boss 名/暴论金句随当前 Boss；水印不变。
- AC3.6 mock 与 api 双引擎下三 Boss 均可完整通关/失败；服务端 bossId 白名单校验。

## R4 可靠性继承

- AC4.1 001 R6 全链路降级继续生效：meta/演出/多 Boss 任一字段缺失或异常不得中断回合。
- AC4.2 新增 SSE 字段向后兼容：旧前端读新服务端、新前端读旧服务端均不报错。
